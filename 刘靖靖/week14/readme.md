各轮优化的真实效果
🥇 模板化（V2）——收益最大，每任务省 ~15K tokens

优化前：每做一个问答站，都要从零写约 600 行 HTML（CSS+JS+交互逻辑 ≈ 35KB 骨架）
优化后：骨架 0 成本复用，每次只需写题库数据 + 一条构建命令
省掉的不是内容，而是重复劳动——这是唯一真正省 token 的优化
🥈 校验脚本固化（V2/V3）——省 token + 省返工

之前每次临时写校验脚本（Node），用完即弃
现在 validate_quiz.js + 构建内置校验：从"写代码"变成"跑命令"，还顺带消灭了"答案集中/索引越界"这类返工
🥉 题库分离 + 持久化 + 难度组卷 + 连线题（V3/V4）——主要是功能价值，不是 token 价值

这些让模板从 ~30KB 涨到 36.3KB，反而略微增加生成成本（每次多输出 6KB 左右）
但换来的是：导入导出换题库、错题本跨会话、随机组卷、连线题——使用价值 >> token 代价
OCR 兜底（V4）——防止"死胡同"

本身不省 token，但避免了"提取不到文本 → 出不了题 → 任务失败"的路径，属于可靠性的保险
关键结论
优化前 → 后，单任务 token 约降 40-50%（骨架 15K + 返工减少），题库数据 43.5KB 是内容本身，省不掉
投资回报率：模板+脚本是一次性投入 ~66KB，之后每个任务省 ~15K tokens——大约 第 5 个问答站任务开始净赚
执行效率：从"手写 600 行 + 反复调试"（分钟级、易错）→ "写 JSON + 一条命令"（秒级、确定性高），这是质量上的质变
坦率说：V3/V4 的功能类优化从纯 token 角度是"负贡献"，但用户价值远大于这点开销——如果你追求极致 token 效率，这些功能可以做开关，但我不建议为 token 牺牲功能
